# Scene Archive Toolkit

Tools for a Scene music archive: automatically check new releases against srrDB, rename and file
them, keep statistics, and browse the archive in a web UI.

Version: see the file `VERSION` and `CHANGELOG.md`.

## Components

| Folder | What it does |
|---|---|
| `processor/` | Incoming Processor: processes everything in `incoming/` (srrDB lookup, CRC check, rename, sort) |
| `archivedb/` | ArchiveDB: search UI over the archive (SQLite, FastAPI, read only) |
| `pipeline/` | Nightly run `scene_nightly.sh`: processor, links, optional mirror, statistics, sorter, with lock and Discord report |
| `tools/` | Statistics (`archive_stats.py`), sorter (`archive_sorter.py`), symlink repair, and a migration tool for old layouts |
| `docs/` | Migration from the old layout (only needed for existing setups) |

## Archive layout (v3)

```
<ARCHIVE_ROOT>/
  incoming/             new releases are dropped here
  scenereleases_srr/    real folders: releases with an srrDB match
  scenereleases_nosrr/  real folders: clean releases that srrDB does not know
  scenereleases/        relative symlinks only, pointing into the two folders above
  incomplete/           CRC errors or missing files
  dupes/                duplicates and superseded versions
  mp3s/                 loose audio files without an SFV
  _sorted_/             generated by the sorter (by artist, genre, year, ...)
```

The archive must be on a **local filesystem**, because symlinks do not work over SMB/CIFS. The
processor therefore runs on the machine that owns the disks (or in a container that has the folder
mounted locally).

## Quick start (fresh installation)

Requirements: Linux, Docker with Compose. For a new archive just create the folder structure
(`mkdir -p /srv/archive/{incoming,scenereleases_srr,scenereleases_nosrr,scenereleases,incomplete,dupes,mp3s}`)
and drop releases into `incoming/`.

1. **Set up the processor and try it**

   ```bash
   cd processor
   cp .env.example .env        # set ARCHIVE_PATH to your archive folder
   docker compose build
   docker compose run --rm processor python incoming_processor.py --dry-run
   ```

   The dry run moves nothing. If the result looks right: `docker compose run --rm processor`.

2. **Set up ArchiveDB**

   ```bash
   cd archivedb
   cp .env.example .env        # set ARCHIVE_PATH
   docker compose up -d --build
   ```

   Open `http://<host>:8000` in a browser.

3. **Run it regularly.** The processor is a single run, not a service. The nightly pipeline runs
   processor, links, statistics and sorter in one go:

   ```bash
   cd pipeline
   cp pipeline.env.example pipeline.env    # set ARCHIVE
   ./scene_nightly.sh --dry-run
   ```

   Then schedule `pipeline/scene_nightly.sh` with cron, see `pipeline/README.md`. With `ARCHIVEDB_URL`
   in the processor `.env` (and both containers in the same Docker network) ArchiveDB updates itself
   after every run.

## Updating

```bash
git pull
cd processor && docker compose build && cd ..
cd archivedb && docker compose up -d --build
```

If you still have the old layout (folder `nomatch`, real folders in `scenereleases`), read
`docs/MIGRATION.md` first.

## Notes

- All scripts carry a version history in the file header. The version number is also shown in the start banner.
- Credentials (Discord webhook, proxy) belong in the `.env` files only, which are not committed to Git.
- srrDB is queried anonymously, no login is needed. Please do not set `REQUEST_DELAY` too low.
- Font `DejaVuSansMono.ttf` in `archivedb/static/fonts/`: free license (Bitstream Vera / DejaVu).
